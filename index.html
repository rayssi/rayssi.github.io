Ma démarche qualitéHow I build quality

La même méthode, que la QA existe déjà ou qu’elle soit à construire de zéro.

The same method, whether QA already exists or has to be built from scratch.

  1. CadrerFrame

    Identifier les parcours critiques, définir la stratégie de test, le périmètre et le plan de recette, préparer les environnements et les jeux de données.

    Identify critical journeys, define the test strategy, scope and acceptance plan, and prepare environments and test data.

  2. SpécifierSpecify

    Analyser les besoins en amont avec les développeurs et le produit (Three Amigos), écrire les critères d’acceptation et les scénarios en Gherkin.

    Analyse needs early with developers and product (Three Amigos), and write acceptance criteria and Gherkin scenarios.

  3. AutomatiserAutomate

    Tests API, tests end-to-end sur les parcours critiques, accessibilité, avec un code de test structuré et relu (Page Object Model, linting).

    API tests, end-to-end tests on critical journeys and accessibility checks, with structured, reviewed test code (Page Object Model, linting).

  4. IntégrerIntegrate

    Lancer les tests dans GitLab CI ou Jenkins à chaque livraison, en nightly et à la demande, ciblés par tags et exécutés en parallèle.

    Run the tests in GitLab CI or Jenkins on every release, nightly and on demand, targeted with tags and run in parallel.

  5. MesurerMeasure

    Rapport Allure à chaque pipeline, alerte Slack aux bons responsables, statistiques mensuelles de flakiness, de durée et d’échecs.

    An Allure report for every pipeline, Slack alerts to the right owners, and monthly statistics on flakiness, duration and failures.

  6. TransmettreHand over

    Documentation, conventions et sessions de partage pour que l’équipe s’approprie les tests et les fasse vivre sans moi.

    Documentation, conventions and knowledge-sharing sessions so the team owns the tests and keeps them alive without me.
